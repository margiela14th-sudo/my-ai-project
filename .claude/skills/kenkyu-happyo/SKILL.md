# 研究発表資料を作る（スライド・研究資料・原稿）

2026年11月の山口県中学校数学教育第二地区研究協議会の資料づくりで決まったやり方をまとめたもの。
見本（このリポジトリ）：`06_制作途中/deck/build_deck.js`（スライド）、`06_制作途中/deck/build_doc.js`（Word・大会誌様式）、`07_完成資料/`（完成品）。

## いちばん大事なこと：根拠のないデータは載せない

研究会では、出典のないデータは一蹴される。数値を1つでも載せたら、次を全部守る。

1. **原典を手元に取る**：PDF・Excel・公式サイトから取る。AIの記憶・まとめサイト・孫引きは使わない。
2. **数値を原典で照合する**：`pdftotext -layout` でページごとに検索し、**該当ページ**を控える。図の凡例・単位・調査年・対象（小学校か中学校か、教諭か全職種か）も確かめる。
3. **出典を書く**：発行者「資料名」該当箇所（表番号・ページ）、公表年月、URL。
   - スライド：各スライドの下に小さく書き、最後に「補足 データの出典一覧」（データ／出典／URL の表）を置く。
   - Word：本文に〔文献1 p.9〕と付け、参考文献は番号・ページ・URL・確認日付き。
4. **自分の計算と統計を分ける**：変化の割合・比例の式・合計などは「発表者が計算」と書く。仮の数値は「仮の数値（実測値ではない）」と書く。
5. **言い過ぎない**：原典の言い方より広く書かない（例：「活用した学校の98%」ではなく「教職員の半数以上が活用した学校のうち98%」）。
6. **過去の自分の資料のデータも照合する**：昔の学級通信やワークシートにも誤りはある（例：桜の開花日 3/27 → 気象庁では 3/25）。直すのは新しい資料だけで、過去資料は書き換えない。
7. 照合の結果は `SOURCES.md` と `02_統計データ/統計データ一覧.md` に残す。

よく使う原典：文部科学省（教員採用選考の実施状況、教員勤務実態調査、「教師不足」に関する実態調査）、国立教育政策研究所（TALIS）、中央教育審議会の資料、気象庁「過去の気象データ検索」。

## 研究上の約束

- 架空の研究成果・生徒の反応・時間削減率・理解度向上を作らない。実測がないものは「検証計画」「期待される効果（見通し）」として書く。
- 過去の実践の事実と、今回の提案を分けて書く。
- 受験者数の減少と教員総数の減少を混同しない。
- 生徒の氏名・成績・振り返りは匿名化してから扱う。写真に生徒が写っていたら使わない。
- 過去資料（Google Drive の原本）は参照のみ。上書きしない。
- 資料をAIで作ったことを隠さない（先生が望むなら冒頭で明示する）。

## スライド（PowerPoint）

- 公式の pptx スキル（`anthropic-skills:pptx`）と pptxgenjs で作る。グラフは編集できるネイティブのグラフにする。
- **1枚1メッセージ**。タイトルは結論の文（「授業準備の時間は、変わっていない」）。本文 22〜26pt、強調する数値 60〜90pt。文字は少なく。
- 全スライドに発表者ノート（話す原稿、先頭に【0:40】のような目安時間）。原稿はノートから書き出す（1分300字換算で時間を計算）。
- 流れの例：表紙 → この資料について → 問題意識 → 今日の流れ → データ → 過去の実践（AIを使う前の実物）→ 改善・提案 → 考察（仮説の要素ごとに 根拠／言えること／まだ言えないこと）→ 利点・欠点・可能性 → 結論 → 参加者への問い → 補足（出典一覧・式の根拠）。
- 作ったら必ず PDF にして画像で全ページを見て、はみ出し・重なり・折り返しを直す（`soffice --headless --convert-to pdf` → `pdftoppm`）。

## 研究資料（Word・大会誌の様式）

- A4縦・余白18mm・**2段組み**（段間7mm）。表題は罫線の枠（題・副題・所属と氏名）。
- 見出し「１．」＝ＭＳ ゴシック11.5pt・下線、小見出し「（１）」＝ＭＳ ゴシック10.5pt、**本文＝ＭＳ 明朝10pt**。
- 図表は段の幅で、図N・表N の通し番号と出典付きのキャプション。最後に＜参考・引用文献＞。
- docx-js で作る（見本 `build_doc.js` の `H1`・`H2`・`P`・`BOX`・`FIG`・`TABLE`）。PDF にして文字の欠けや改ページを確認する。
- 明朝が出ない環境では `fonts-ipafont-mincho` を入れ、fontconfig で ＭＳ 明朝 → IPAMincho に当てる。

## 仕上げ

- 想定質疑（出典・データの限界・実測していないこと・AIの誤りへの対処）を作る。
- 完成品は `07_完成資料/` に置き、`PROGRESS.md`・`DECISIONS.md`・`SOURCES.md` を更新してコミットする。
- 先生にはファイルと、変えた点・数値を直した点・時間の見込みを短く報告する。講師に渡したあとの数値の修正は、必ず目立つように伝える。
