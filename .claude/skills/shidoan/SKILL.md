# 学習指導案（文字ベース）を作る

学習指導案＝文章と表で書く指導案。板書型指導案（黒板の図が中心）とは別物で、そちらは `bansho-shidoan` を使う。両方を頼まれたら、先に板書型を作り、その「板書のみ.png」を本案の「板書計画」に貼る。

## 守ること（研究上の約束）

- 生徒の実態・反応・成績を**作らない**。分からないところは `【要記入】` と書いて先生に返す（特に「生徒観」「日時・学級・指導者」）。
- 生徒の氏名・成績・振り返りは書かない。外部のAIに渡す前に匿名化する。
- 「予想される生徒の反応」は予想として書く（事実のように書かない）。実践後の記録と混ぜない。
- 評価規準は3観点（知識・技能／思考・判断・表現／主体的に学習に取り組む態度）。文末は「〜している」「〜しようとしている」。根拠は学習指導要領解説と国研「指導と評価の一体化」のための参考資料。
- 教科書・データ・先行実践を使ったら、出典（発行者・資料名・年・ページ）を `sources` に書く。
- 過去の指導案は上書きしない。新しいファイルとして作る。

## 手順

1. **聞き取る**（足りない分だけ。分かっていることは聞かない）
   - 学年・単元・本時が何時間目か・本時のねらい
   - 元にする過去の指導案や授業記録があるか（あれば必ず読んで、良さを残す）
   - 使う教材・ICT・AI、時間配分（50分）
2. **JSON を書く**：`examples/sample_shidoan.json` を写して書き換える。項目は次のとおり（不要な項目は省いてよい）。
   - `title`（例「第３学年　数学科学習指導案」）、`header`（日時・学級・指導者など。右寄せで並ぶ）
   - `unit`、`unitGoals`（配列）、`criteria`（knowledge / thinking / attitude）
   - `about`（students / material / teaching）
   - `plan`：`[{stage, hours, content, eval, current:true(本時)}]`
   - `lesson`：`goal`、`eval`、`problem`（課題の枠）、`flow`：`[{stage, min, activity, notes}]`
     - `activity` は「○発問」「・予想される反応」で行を分ける（`\n`）
     - `notes` は「・留意点」「◆評価（観点・方法）」「☆ICT・AI」の記号で書く
   - `boardImage`（板書の画像。JSON からの相対パス）、`sources`
3. **作る**：
   ```bash
   node .claude/skills/shidoan/scripts/build_shidoan.js 指導案.json 出力.docx
   ```
   `docx` が見つからないと言われたら、`NODE_PATH=<docx の入った node_modules>` を付けるか、作業フォルダで `npm install docx sharp` を実行する（このリポジトリでは `NODE_PATH=06_制作途中/deck/node_modules`）。
4. **見て確かめる**：`soffice --headless --convert-to pdf 出力.docx` → `pdftoppm -r 60 -jpeg` で画像にして、表のはみ出し・改ページ・文字化けを確認する。
5. **渡す**：Word と PDF を渡し、`【要記入】` の場所と、作った内容のうち先生の確認が必要な点（評価規準、時間配分など）を短く伝える。

## 様式（既定値）

- A4縦・余白 上下18mm 左右20mm、見出し＝ＭＳ ゴシック、本文＝ＭＳ 明朝 10.5pt
- 「1　単元名」「（１）本時の目標」の番号の付け方
- 本時の展開の表：段階（時間）｜学習活動 ○主な発問 ・予想される生徒の反応｜指導上の留意点 ◆評価 ☆ICT・AI
- 学校や研究会の様式が指定されたら、そちらに合わせて `build_shidoan.js` を直す（列の幅は `TABLE(..., [12, 50, 38])` の比）。
